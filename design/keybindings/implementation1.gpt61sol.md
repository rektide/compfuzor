# Situation and outcome

The parent accepted the first interface/processor/domain slice and asked for a
coherent TypeScript consumer assembly/delivery slice using the Mise2/Zim2 CONFIG
world. Root adoption, contribution identity and native candidate-closure validation
were the next seams—not another renderer or transactional executor.

**Implemented:** explicit consumer capture and placement, adopted root assembly,
native validation against private candidate layouts, and publication through the
existing CONFIG runner. Registration is a reusable coherent batch with one
assembly callback. The installed omnibus runtime supports both assembly and
registration outside the checkout.

**Not performed:** live deployment, broad Vicinae/KDE cutover, source-builder
changes, Effect migration, source-inventory persistence or autogenerated producer
participation. Unrelated user/parent work was excluded from explicit-path commits.

# Consequential interfaces and choices

| Seam | Choice and reason |
|---|---|
| Execution/publication | The consumer captures and prepares input bytes; `config-run.sh` remains the only artifact commit/rollback implementation. |
| Generic validation extension | Optional `transaction_validate` runs after every candidate exists and after immediate legacy validators, before any check/stdout/publication result. Every candidate, including unchanged outputs, remains in a versioned map. |
| Generic staged link | Per-recipe `link` declares an absolute target. The candidate contains captured bytes for validation; publication stages a sibling symlink and reuses the existing backup/move loop. |
| Dynamic recipe participation | An explicit runtime-spec `leaf` can select the already-deployed shared concat processor. Dynamic source membership does not require writing executable wrappers or pretending CONFIG has a candidate DAG. The per-name leaf remains the default. |
| Block support | Generic compiler settings now support `block.id` for an explicit file and recipe-wide `block.comment`. A reusable TS CONFIG adapter also prepares a private adopted insertion area through the existing block-in-file CLI. |
| Root authority | Missing roots use a template. Existing roots require an explicit adopted area; no second Umbriel table or unrelated TOML rewrite. Existing baseline/personal text is not implicitly rewritten from request settings. |
| Stable membership | Block identity is `keybinding/<target>/<id>`. YAML IDs are authoritative for actions/bindings; native source IDs come from explicit source metadata. Filenames remain provenance/placement, not competing identity. |
| Native user files | Same `NativeSource` interface as generated material: explicit ID/path/format/order, direct/copy/link placement, include or Niri inline, and declared enabled/disabled registration state. |
| Copy authority | Assemble/seed preserve existing local files and links; normal reassembly consumes edited copies. Refresh is explicit replacement. Missing selected copies do not secretly read the producer. |
| Validation authority | Validate the actual effective root using candidates/captured files. Also admit shadowed generated definitions under the same context in a separate validation-only envelope; never overwrite user-copy selection to validate defaults. |
| Registration | `withInputBatch` uses existing delivery primitives, preserves selected disabled slots, and invokes assembly exactly once after all entries are installed. Normal failure restores prior entries. There is no concurrent-reader isolation or crash-atomicity claim. |

The distinction between actual-root validation and default-material admission
emerged from implementation evidence: a valid edited copy can shadow an invalid
new canonical definition. Validating only the effective root would then publish
invalid newly generated material. A standalone fragment check would lose context.
The additional envelope admits those unused definitions before the effective root,
without changing live includes; the effective root is independently validated first.

# What became possible

- Copy/link seeding and explicit refresh are staged outputs of the existing CONFIG
  transaction. Check mode renders and validates prospective state without creating
  missing user placements or roots.
- Ordinary reassembly preserves an edited user copy while a linked generated
  definition tracks a changed action. An edited native copy can still assemble
  when its unused donor has disappeared.
- Direct native user files, Niri direct/copy inline, generated definitions and
  companion material use the same selection/placement path. Inline relative
  includes resolve from the selected body location, not accidentally the root.
- Missing roots have readable baseline/contribution/personal skeletons. Adopted
  roots preserve unrelated text; path/order switches replace the same named block.
- Root closure validation observes pending definition/placement bytes, not old live
  files. Invalid prospective native actions preserve managed outputs and link topology.
- Normal registration failures restore a coupled action/binding batch, including
  disabled state, rather than issuing two immediate-rebuild remote puts.
- Normalized paths and parent-directory aliases are checked before output writes;
  observed root/source/parent-topology changes abort instead of stale overwrite.
- The bundle carries YAML/KDL/TOML dependencies and executes assembly/registration
  in an isolated deployment without source files or node_modules.

# Remaining tensions and next slice

1. **Source membership persistence is still explicit caller state.** The request
   supplies ordered paths; registration does not yet append/update a durable
   contributor inventory. This is the next seam for producer participation, not
   a reason to add a second executor. Keep exact declared membership and disabled
   state; do not discover arbitrary deployments from PATH or admit suffix-wide
   native scans.
2. **Autogenerated producer participation is not implemented yet.** Next, thin
   Python/Ansible glue can package general named declarations into singular
   `action/` and `keybinding/` resources, generate shared-runtime installer entries,
   and bind an explicit target/consumer request. The installed API now exists to
   register and assemble once; producers should not author CONFIGS/BINS per binding.
3. **Bootstrap policy versus existing-root policy remains deliberate.** Template
   baseline/personal fields affect missing roots. Existing text stays author-owned.
   The maintained Umbriel root can be explicitly adapted to the array insertion
   contract after this checkpoint, not silently transformed now.
4. **Legacy block CLI availability affects preparation cost.** The inspected npm
   package lacks the archive's newer public library API, so shared preparation
   uses verified CLI behavior. A future published pure API can replace this adapter
   without changing the consumer semantics; no unpublished dependency is assumed.
5. **Concurrency and crash recovery remain bounded.** Guards detect observed changes,
   not every race. Registration rollback and CONFIG publication are normal-failure
   operations, not one crash-atomic transaction or isolation from other assemblers.
   Cleanup failure after successful publication does not imply the mutation never
   happened; callers must not advertise exactly-once retry semantics.
6. **Native validation checks native semantics, not app availability.** Spawn argv
   and explicit shell bodies are never executed during preparation. A missing
   selected validator fails rather than installing or skipping a target.

Proposed next coherent implementation: durable **explicit contributor membership
plus automatic packaging/installer participation**, using the current consumer
request and registration seam. Keep source-builder playbooks as builders and
continue isolated consumer tests. A second contributor should need declarations
and target/context binding only. Vicinae cutover and live deployment remain gates
for the parent, with KDE preserved.
