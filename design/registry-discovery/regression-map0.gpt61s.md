# Checkpoint and scope

The registry/native path exists; completing its cutover requires **migrating fixture entry contracts without losing native/action acceptance**, proving combined first installation and both isolated registry policies, and correcting maintained guides. Restoring old producer-per-adapter wrappers or shared hardcoded profile defaults would undo the approved direction.

This is independent read-only investigation plus this one owned report. No runtime, library, tests, existing docs or indexes were edited; no integration tests, deployments or services were run. Sources were inspected while another Sol medium implements prospective consumer admission and explicit provider/consumer policy injection. Interface observations below describe the inspected predecessor; they are not a declaration that the concurrent implementation still lacks those changes.

Classification used throughout:

- **A — retained:** behavior/coverage must survive the cutover.
- **B — obsolete entry expectation:** replace old producer target wrappers, hardcoded common profiles, or adapter-as-receiver assumptions; do not restore them.
- **C — unresolved:** implementation or evidence needed, not just changing a filename.
- **D — isolation prerequisite:** caller-supplied provider **and** consumer policy required before safe SYSTEM registry execution. A test may be A+B+D simultaneously.

The [ownership clarification](/design/registry-discovery/ownership0.gpt6a.md#the-ownership-contract-comes-first), [rendezvous design](/design/registry-discovery/rendezvous0.gpt6a.md#who-does-what), and [force decision](/design/registry-discovery/selection0.gpt6a.md#operator-decision) govern this audit. All six upstream Figments contracts are accepted; repeating that research is unnecessary.

# Public paths and minimum fixture contract

## Producer delivery is now one admitted offer

[Generator lines 159–201](/library/filter_plugins/keybindings_compile.py#L159-L201) packages exact producer YAML, a version-1 manifest, owned `keybindings/selection.json`, passive register/status entries, and **one `install-keybindings.sh`** using `keybindings.mjs install-offer`. Typed actions use `operation: "install-offer"`, exact manifest/producer/selection, not a scalar native receiver. Host-only per-receiver wrappers still exist ([lines 210–229](/library/filter_plugins/keybindings_compile.py#L210-L229)); not every occurrence of `install-keybindings-niri.sh` is obsolete.

Minimum replacement fixture:

1. Keep authoritative YAML IDs, exact absolute manifest resources, producer/order, stock CONFIG runner/concat and actual bundled runtime. In the manifest `targets` means **native adapter eligibility**, not receiver IDs. Current generator emits both native adapters for a nonempty explicit receiver map; tests expecting `targets == ["umbriel"]` for a receiver subset must instead assert the selection file ([lines 168–189](/library/filter_plugins/keybindings_compile.py#L168-L189)).
2. Package an owned consumer descriptor: `{version:1,id:"deck-main",adapter:"niri",audience:"user",profile:{path:"/owned/keybinding-deck-main.json"},contexts:["desktop"],defaultContext:"desktop",enabled:true}`. The profile still has `target:"niri"` and explicit context roots. IDs and adapters are distinct ([domain schema](/runtime/keybindings/registry.ts#L46-L85)).
3. Expose that descriptor through the appropriate consumers registry, normally by host install or passive `register-keybindings-consumer-<id>-<audience>.sh`. A producer's profile override does **not** make a missing registry identity exist. Older fixtures that only render a host and immediately install a producer need deliberate advertisement first, or the newly implemented explicit prospective-owner contract for a combined deployment.
4. Assert `{version:1,receivers:null}` for default-all; `receivers:[]` for explicit no-delivery; entries `{id,profile?,context?,scope?,actionContexts?}` for a subset. Repeated CLI `--target` names **receiver IDs** and may only narrow a declared subset ([batch lines 175–238](/runtime/keybindings/invocation.ts#L175-L238)). `consumer` in playbook target settings still compiles to a profile selector, not a descriptor or rendezvous slot.
5. Invoke producer `install.mjs` for authored aggregate acceptance, or `install-keybindings.sh --target <id>` to avoid unrelated authored service bodies. Move `COMPFUZOR_NIRI_PROFILE`/`COMPFUZOR_UMBRIEL_PROFILE` assertions to consumer-owned descriptor/profile selector behavior. They no longer constitute shared producer defaults.
6. Keep named user/system action contexts and audience-separated advertisements. A user descriptor cannot be reused as the system descriptor simply because its profile contains both contexts.

## Isolation is a public policy concern, not an environment trick

[BatchRequest lines 59–67](/runtime/keybindings/invocation.ts#L59-L67) accepts a consumer policy in the observed predecessor, while provider publication constructs normal defaults at [lines 148–154](/runtime/keybindings/invocation.ts#L148-L154). Owned-host admission independently constructs consumer defaults ([runtime lines 110–129](/files/config/keybindings/runtime.ts#L110-L129)). Consequently passing a temporary native root or only a consumer policy is insufficient.

Before any SYSTEM test, use the successor's **invocation-bound provider+consumer policy interface** in producer batches, owned-host operations, and typed action transport. Each policy must have `scope:"system"`, absolute disposable ordered roots and a contained write root; every generated passive endpoint must receive its own explicit roots as well. The generic registry CLI's `--root`/`--write-root` capability is not evidence that the native install-offer parser accepts those same flags. Use the verified new interface, do not guess flag names or invent hidden test-only env overrides.

For USER tests set all of `HOME`, `XDG_CONFIG_HOME`, `XDG_DATA_HOME`, `XDG_STATE_HOME`, `XDG_CACHE_HOME`, **`XDG_DATA_DIRS` and `XDG_CONFIG_DIRS`** to disposable trees. Existing helpers often clear only HOME-relative home values and inherit shared search roots. They can observe foreign registrations even when their writes remain home-local. Explicit paired roots make admission deterministic; ensure those bound policies survive body changes to HOME/XDG and transport serialization. Stub `systemctl` and reject sudo/SteamOS commands: HOME does not isolate the session bus.

# What the generated proof actually proves

[Latest generated proof](/tests/integration/registry_keybindings_generated.test.py#L19-L39) **does not invoke the full media-keys/Niri/Umbriel playbooks**. It extracts an allowlist of their vars (including authored BINS and ETC_FILES), runs real generation/materialization subtasks, and executes generated entries against the committed bundled artifact. This is strong generator/runtime proof, not full default-placement/package/provisioning coverage. The older full-playbook consumer/Media Keys/Vicinae/SteamOS scripts and [action-placement's import-playbook wrapper](/tests/integration/action_placement.test.py#L30-L47) supply different evidence that should survive.

The latest proof sets isolated HOME plus **all major XDG roots/search dirs**, does not deploy packages/services, and uses actual stock CONFIG workers, block-in-file and native validators. Its PATH is constructed at [lines 46–52](/tests/integration/registry_keybindings_generated.test.py#L46-L52); it does not fake niri/umbriel or systemctl. It therefore depends on separately installed Node, Ansible/PyYAML, jq, block-in-file, Niri/Umbriel and Umbriel's baseline/include environment. It is USER-only, with three receivers (two Niri adapters), not SYSTEM policy proof.

Retain its [lines 58–120](/tests/integration/registry_keybindings_generated.test.py#L58-L120): exact owned Zim offer refs/active+disabled fragments; render does not register; passive consumer publication before native activation; no retired producer wrapper; default fan-out; arbitrary receiver ID distinct from native format; explicit disabled early failure; forced subset/default without rename; preserved consumer group disable; mask veto even under force/passive current; actual native rejection preserving copied YAML/root/membership; check/assembly doesn't advertise, ordinary host installation does.

Not established by this proof: combined host+producer first install, SYSTEM registry isolation, two-producer ordering/shrinking/empty acceptance, edited-copy/link refresh acceptance, detailed Media Keys/Vicinae command semantics, full playbook default placement, runtime changed/canonical/deployed sourcing, Zim registry consumption, or global transactional fan-out. [Batch execution](/runtime/keybindings/invocation.ts#L331-L355) is sequential per-receiver CONFIG commit: later rejection need not undo earlier receiver success, and provider advertisement may remain after native rejection. Add an explicit partial-success assertion rather than claim batch atomicity.

The [first native checkpoint](/design/registry-discovery/implementation1.gpt61s.md#dependency-closure-and-checks) reports focused **8 files/46 tests**, checks/build and this generated proof passing. Its broad combined native Vitest run exceeded 120 seconds. That timeout is **not a passing regression result**, and this audit ran no substitute checks.
