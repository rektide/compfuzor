# Tool-version pins belong to build-mise, not Ansible's render lane

Compfuzor currently writes `DIR/.tool-versions` or `DIR/mise.toml` from `gen_tool_versions.tasks` as an Ansible filesystem artifact, registers a repo-root `LINKS` record, and appends `mise install` to `install.sh`. A link is needed because mise/asdf resolve the physical cwd through `DIR/repo` into the archive and cannot see the pin in `DIR`. But repo-root files shipped by upstream must never be clobbered; today an upstream-tracked version file causes a render failure, while a new generated symlink can appear in jj `@` and Git status on subsequent renders.

This is a second, independently reviewable change after the jj repository split. The archive runner should own only checkout/transport/recovery and have **no** version-manager knowledge. `gen_tool_versions.tasks` retains `TOOL_VERSIONS`/`MISE_VERSIONS` merging but contributes one `build-mise.sh` executable rather than emitting `ETC_FILES`, `LINKS`, or the old `install.sh` snippet. This executable runs in the bin-run lane, whose noninteractive zsh parent loads mise shims; it can also be invoked through the generated `build.sh` compositor. The generated executable makes the deployment pin file at build time, then considers the repo-root link, then calls `mise install`.

## Build-mise contract and ordering

1. Resolve pins during synthesis, but write the deployment pin file only when `build-mise.sh` executes. Write to a temporary file in `DIR`, compare/move only when content differs; `MISE_VERSIONS` wins the file-format choice when present, merging `TOOL_VERSIONS` as its base. The bin uses the standard shell wrapper and `bypass: [MISE]`: `COMPFUZOR_MISE_BYPASS=1` skips the entire body (including pin emission and install). The existing `TOOL_VERSIONS_LINK_BYPASS` remains a link-only opt-out. A separate `COMPFUZOR_MISE_LINK_FORCE=1` permits replacing an occupied file or symlink intentionally; it is never the default.
2. If there is a distinct checkout (`REPO_DIR` with `.git`), idempotently append a **root-anchored basename** to that clone's `.git/info/exclude` **before** creating a link or invoking `mise install`. jj 0.45.1 and Git honor `.git/info/exclude` for untracked files. A tracked upstream file is not hidden by this rule; the exclude lives only in the local clone and is not committed or pushed. This ordering prevents newly generated links from entering jj snapshots. For a legacy managed link already snapshotted by jj, the exclude cannot retroactively untrack it: after exclusion the operator may run `jj file untrack <name>` deliberately; no implicit history surgery is performed in a build bin.
3. If the repo path is absent, create the link pointing at `DIR`'s pin. If it is already a link to that pin, leave it alone. Otherwise preserve the existing path, emit a loud notice and a labeled unified diff against the newly generated pin (read-only), and **continue to `mise install`**. Do not treat cross-file manager selection as permission to overwrite an upstream file. With the explicit force variable, replace only a regular file/symlink and print a warning; don't recursively delete directories.
4. The run lane iterates raw `BINS` in list order, not the compositor's phase order. Prepend `build-mise.sh` to the BINS merge so automatic runs reach it before `build-nodejs.sh` and other tool consumers. Mark it `phase: packages` so the `build.sh` compositor also schedules it before `main` builds, independently of declaration order. On a bypass it skips cleanly and later build bins still follow their own guards.

Build scripts ordinarily have their stdout hidden in Ansible's result output. To make occupied-path warnings and the diff visible **at end of the play**, `build-mise.sh` emits prefixed notice lines in its stdout; `bins_run.tasks` registers loop results, and an immediately following task appends the notices into the repository-notice fact and notifies the already-registered handler. The skip headline gets a distinct format; diff lines are emitted as ordinary `REPO NOTICE` lines. Direct invocation of the bin prints those lines as well. A bin whose body fails remains a normal failed build; a diff is not a failure.

## Alternatives rejected, limits

- Not render-time `ETC_FILES`/`LINKS` plus a post-fetch override in `repo_jj_archive.tasks`: generation happens before first clone, and version-manager policy does not belong to a repository transporter. It also breaks clean separation of the two deliverables.
- Not a render-time Git or jj clean/reset. Ignores are clone-local and only apply to *untracked* files. The build bin handles generated links and warns about other file ownership without rewriting commit history.
- Not silently adopting upstream's version file over Compfuzor's pin, and not stopping a build solely because the two differ. The labeled diff exposes that decision to the operator; `COMPFUZOR_MISE_LINK_FORCE` is the opt-in to replace the existing path.
- For deployments with no repo, still emit the pin and run `mise install` in `DIR`; there is no `.git/info/exclude` or repo link to create. Regular Git and jj archive paths share this same build step.
